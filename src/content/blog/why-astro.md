写博客这件事，我断断续续试过很多次。最开始用现成的博客平台，后来换成各种静态站点生成器，每次都在"配置"上花掉的时间比"写作"还多。

这一次我决定换个顺序：**先把写作路径铺平，再考虑别的**。

## 为什么不是 Next.js

如果你要的是一个"会长成产品的网站"，Next.js 几乎是标准答案。但博客不是产品。

我统计过自己过去的博客使用方式：99% 的时间在做两件事——读文章、写文章。这两件事都不需要客户端路由、状态管理，更不需要一个 Node 服务常驻。为它们引入一整套 React 运行时，属于典型的**给自己找活干**。

有一个很具体的细节让我放弃了 Next.js：默认构建出来的 JS 体积。一个纯阅读的页面塞进几百 KB 的脚本，用户什么都没做，先等下载。这不是性能优化能彻底解决的问题，而是框架定位带来的必然成本。

## 为什么不是 Hugo

Hugo 的构建速度是真的快，几千篇文章也是秒级。如果我的诉求只是"一个可以一直跑下去的静态博客"，Hugo 完全够了。

问题出在我想改样式的那一刻。Go template 的语法需要重新学一遍，变量作用域、管道操作、partial 传参……每次想调一个卡片样式，我都要去翻文档。**这种"每次动手都要重新热身"的成本，对一个想长期写下去的博客来说太贵了。**

还有一个现实因素：我想加一点交互（比如首页按分类筛选文章），在 Hugo 里只能手写原生 JS 并自己维护和模板的耦合关系。

## Astro 让我舒服的三个点

### 一、默认零 JavaScript

Astro 的核心思路是：**默认生成纯 HTML，只有你明确标记为交互的组件才带上 JS。**

这意味着我写一篇八百字的随笔，产出的就是一个八百字的 HTML 页面。没有 hydration，没有运行时。写代码高亮、目录高亮这些功能时，我用原生的 `IntersectionObserver` 就够了，几行脚本，零依赖。

### 二、Markdown 是一等公民，不是插件

内容放在 `src/content/blog/` 下，frontmatter 用 Zod schema 约束：

```ts
const blog = defineCollection({
  loader: glob({ pattern: '**/*.md', base: './src/content/blog' }),
  schema: z.object({
    title: z.string(),
    pubDate: z.coerce.date(),
    tags: z.array(z.string()).default([]),
    category: z.enum(['tech', 'life', 'note']).default('note'),
    draft: z.boolean().default(false),
  }),
});
```

写错字段名会在构建时报错，而不是在页面上渲染出一个空白。这种**早期的、明确的失败**，比运行时才发现问题舒服太多。

### 三、想要"高级感"时不用换技术栈

我原本担心"默认零 JS"意味着样式能力受限。实际用下来恰恰相反：因为输出是纯 HTML，我可以放心地用 CSS 做各种效果——宣纸纹理、墨色层次、朱红点缀、滚动入场动画——不用担心和服务端状态打架。

这套水墨主题就是这么做的：一套 CSS 变量控制全局配色，暗色模式只是换一组变量值。

```css
:root {
  --bg: #f7f4ed;                      /* 宣纸底 */
  --text: #1c1917;                    /* 焦墨 */
  --brand: var(--color-brand-600);    /* 主色：重墨 */
  --brand-text: var(--color-seal-600);/* 强调：朱红 */
}

html.dark {
  --bg: #14110f;
  --text: #ebe6dd;                    /* 宣纸白 */
  --brand: var(--color-brand-300);
  --brand-text: var(--color-seal-300);
}
```

## 几个真实遇到的坑

| 问题 | 原因 | 解决方式 |
| --- | --- | --- |
| 暗色模式首屏闪白 | 主题脚本在 DOM 渲染后才执行 | 把主题初始化内联进 `<head>`，同步执行 |
| 卡片入场动画在无 JS 时内容不可见 | 默认 `opacity: 0` 等待 JS 加类 | 只在 JS 可用时才应用初始隐藏 |
| 代码块在暗色模式下看不清 | 单一高亮主题 | Shiki 配置 `themes`，深浅两套 |

第二条尤其值得说。我一开始的写法是给所有卡片一个 `opacity: 0`，等 JS 加载后再触发动画。结果在网速慢或者 JS 被禁用的情况下，**页面是一片空白**。现在的做法是先判断 JS 是否可用，只在可用时才隐藏元素——渐进增强的老规矩，但真的容易忘。

## 现在回头看

选框架这件事，我的判断标准变化很大：

- **以前**：哪个功能多、哪个生态大、哪个看起来更"现代"
- **现在**：哪个能让我在三年后，仍然愿意打开编辑器写一篇文章

按第二条标准，Astro 是目前的最优解。它不试图解决所有问题，但它把"写文章"这件事做得足够顺畅，并且在我偶尔想折腾一下的时候，也留足了空间。

下一篇我会具体写写这套主题的实现，包括配色方案是怎么定的、卡片布局踩了哪些坑。
